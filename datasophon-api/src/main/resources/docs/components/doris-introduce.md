# Apache Doris 组件介绍

## Apache Doris 是什么

Apache Doris (曾用名 Palo) 是一个开源的、基于 MPP（Massively Parallel Processing，大规模并行处理）架构的实时分析型数据库。它旨在为用户提供亚秒级查询响应时间，支持对海量数据进行即席查询和多维分析。Doris 兼容 MySQL 协议，并支持标准 SQL，使得用户可以轻松上手并与现有工具集成。

Doris 的设计目标是易用性、高性能和高可用性。它特别适用于报表分析、即席查询、数据湖联邦查询、统一数仓构建等场景。

## 核心架构

Apache Doris 采用简洁的 Master-Slave 架构，主要由两类进程组成：Frontend (FE) 和 Backend (BE)。此外，还可以通过 Broker 进程访问外部存储系统。

### Frontend (FE)

FE 是 Doris 的前端节点，负责元数据管理、客户端连接管理、查询规划与优化、以及集群管理等功能。FE 节点可以部署多个以实现高可用（HA），其中一个 FE 为 Master 节点，其余为 Follower 节点。Master 节点负责所有元数据的写入操作，并将其同步给 Follower 节点。

**主要职责：**
-   **元数据管理**：存储和管理数据库、表、分区、副本等元数据信息。
-   **SQL 解析与优化**：接收用户的 SQL 请求，进行词法分析、语法分析、查询优化，并生成执行计划。
-   **查询调度**：将执行计划分发给 BE 节点执行。
-   **集群管理**：监控 BE 节点状态，负责 BE 节点的上线、下线，以及数据的均衡和修复。
-   **用户权限管理**：管理用户账户和权限。

### Backend (BE)

BE 是 Doris 的后端节点，负责实际的数据存储和查询执行。数据以列式存储格式存储在 BE 节点上，并且可以进行分区和分桶。

**主要职责：**
-   **数据存储**：以列存方式存储表数据，支持数据压缩。
-   **查询执行**：接收来自 FE 的执行计划片段，并执行数据的扫描、过滤、聚合、连接等操作。
-   **数据管理**：负责数据的导入、Compaction（数据合并）、Schema Change（表结构变更）等。
-   **副本管理**：管理数据的副本，确保数据的高可用性。

### Broker (可选)

Broker 是一个独立的无状态进程，用于辅助 Doris 与外部存储系统（如 HDFS, S3, BOS 等）进行数据交互，主要用于数据导入（Broker Load）和数据导出。

**主要职责：**
-   **访问外部存储**：提供访问 HDFS、S3 等外部文件系统的能力。
-   **数据传输**：在 Doris 和外部存储之间传输数据。

## 关键特性

Apache Doris 凭借其强大的特性，能够满足各种复杂的分析需求：

### MPP 架构 (Massively Parallel Processing)

Doris 采用 MPP 架构，查询会在所有相关的 BE 节点上并行执行，充分利用集群的计算资源，实现高性能的即席查询。

### 列式存储 (Columnar Storage)

数据在 BE 节点上按列存储。这种方式对于分析型查询非常友好，因为查询通常只涉及表中的部分列。列存可以显著减少磁盘 I/O，并提高数据压缩率。

### 向量化查询执行 (Vectorized Query Execution)

Doris 在查询执行层采用了向量化执行引擎。数据以列式批处理（Batch）的方式进行处理，而不是逐行处理。这减少了函数调用开销和虚函数调用，更好地利用了 CPU 缓存和 SIMD 指令，从而大幅提升查询性能。

### 数据分区与分桶 (Partitioning and Bucketing)

-   **分区 (Partitioning)**：Doris 支持对表数据进行分区，通常基于时间维度。分区可以将大表切分成更小的、易于管理的数据块，便于数据的生命周期管理和查询剪枝。
-   **分桶 (Bucketing)**：在每个分区内，数据会根据分桶键（Bucket Key）进行哈希分桶，分布到不同的 Tablet（数据分片）中。分桶有助于数据的均匀分布和查询的并行处理。

### 多样化的数据模型

Doris 提供了三种主要的数据模型以适应不同的业务场景：

-   **Aggregate Key Model (聚合模型)**：适用于需要预聚合的场景，例如统计报表。相同聚合键的行在导入或 Compaction 过程中会被聚合成一行，用户可以指定聚合函数（SUM, MIN, MAX, REPLACE）。
-   **Unique Key Model (唯一键模型)**：适用于需要保证主键唯一性的场景，例如需要按主键进行更新的业务数据。Doris 会保证相同唯一键的数据只保留最新导入的一行。
-   **Duplicate Key Model (明细模型)**：适用于存储原始明细数据，不对数据进行任何聚合或去重。每一行导入的数据都会被完整保留。

### Rollup 与物化视图 (Rollup and Materialized Views)

-   **Rollup (上卷)**：用户可以为基表（Base Table）创建 Rollup 索引（实质上是预聚合的表）。Rollup 包含了基表的部分列，并且可以有不同的排序键和聚合方式。查询时，Doris 会自动选择最优的 Rollup 来加速查询。
-   **物化视图 (Materialized View)**：物化视图将查询结果预先计算并存储起来。当基表数据发生变化时，物化视图会自动（或手动）刷新。这对于固化复杂查询、加速高频查询非常有效。

### SQL 支持 (MySQL 协议兼容)

Doris 兼容 MySQL 5.7 协议，并支持大部分标准 SQL-2003 语法。用户可以使用熟悉的 MySQL 客户端（如 `mysql-client`、Navicat、DBeaver）或 JDBC/ODBC 驱动连接和操作 Doris。

### 高可用性与可扩展性 (High Availability and Scalability)

-   **FE 高可用**：FE 节点支持部署多个副本，通过选举机制保证 Master 节点的可用性。元数据在 FE 节点间通过 BDBJE (BerkeleyDB Java Edition) 进行同步。
-   **BE 高可用**：数据在 BE 节点上可以存储多个副本（通常为3副本）。当某个 BE 节点故障时，系统会自动切换到其他副本，保证数据的可用性和查询的连续性。
-   **在线扩缩容**：FE 和 BE 节点都支持在线扩容和缩容，无需停止服务。扩容 BE 节点后，数据会自动进行均衡。

### 联邦查询 (Federation Query)

Doris 支持通过外部表（External Table）功能查询位于 MySQL、Elasticsearch、Hive、Iceberg、Hudi 等外部数据源的数据，实现数据湖联邦查询，无需数据迁移即可进行统一分析。

### 多种导入方式

Doris 提供多种灵活高效的数据导入方式，如 Stream Load, Broker Load, Routine Load, Spark Load 等，满足不同场景下的数据加载需求。

## 常见用例

Apache Doris 的高性能和易用性使其在以下场景中得到广泛应用：

-   **固定历史报表分析**：如销售报表、运营报表、财务报表等。
-   **即席查询（Ad-hoc Query）**：数据分析师或运营人员根据需求灵活地进行数据探索和分析。
-   **交互式数据分析**：通常与 BI 工具（如 Tableau, Superset, Metabase）集成，提供自助式数据分析平台。
-   **用户行为分析**：分析用户在网站或 App 上的行为路径、漏斗转化等。
-   **日志分析**：对服务器日志、应用日志进行存储和分析，用于监控、排障和审计。
-   **统一数仓构建**：作为核心的分析型数据库，整合来自不同业务系统的数据，构建企业级数据仓库。
-   **数据湖联邦分析**：直接查询数据湖中的数据，无需ETL，简化数据链路。
-   **高并发点查询**：虽然主要为 OLAP 设计，但通过合理的表设计和优化，也能支持一定并发的点查询场景。
