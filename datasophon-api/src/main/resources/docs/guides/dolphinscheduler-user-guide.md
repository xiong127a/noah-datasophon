# Apache DolphinScheduler 用户指南

## 开始使用

本指南将引导您完成 Apache DolphinScheduler 的基本使用，包括初步的系统了解、安装概览和用户界面熟悉。

### 系统要求

在安装 DolphinScheduler 之前，请确保您的环境满足以下基本要求：

-   **操作系统**: Linux (推荐 CentOS 7+, Ubuntu 16.04+)
-   **JDK**: 1.8+ (所有服务组件都需要)
-   **注册中心**: Apache ZooKeeper 3.5.5+ (用于服务注册、发现和 Master 选举)
-   **数据库**: PostgreSQL (9.4+) 或 MySQL (5.7+) (用于存储元数据)
-   **硬件**: 根据集群规模和负载，Master 和 Worker 节点需要足够的 CPU、内存和磁盘空间。

### 安装概览

DolphinScheduler 的安装涉及多个组件的部署和配置。以下是简化的安装步骤概述：

1.  **环境准备**: 确保所有节点满足 JDK、网络（IP规划、主机名解析、端口开放）等要求。
2.  **下载安装包**: 从 Apache DolphinScheduler 官网下载最新的稳定版二进制包。
3.  **部署数据库**: 初始化 DolphinScheduler 所需的数据库和表结构（通常有 SQL 脚本提供）。
4.  **部署 ZooKeeper 集群**: 如果尚未有可用的 ZooKeeper 集群，请先部署。
5.  **部署 MasterServer**: 解压安装包，修改 `conf/config/install_config.conf` (或相应版本的配置文件) 和 `conf/common.properties` (或 `dolphinscheduler_env.sh`)，配置数据库连接、ZooKeeper 地址等。然后启动 MasterServer 进程。
6.  **部署 WorkerServer**: 在 Worker 节点上解压安装包，进行类似配置，确保 Worker 能连接到数据库和 ZooKeeper。然后启动 WorkerServer 进程。
7.  **部署 ApiServer**: 解压安装包，配置数据库和 ZooKeeper，启动 ApiServer 进程。
8.  **(可选) 部署 LoggerServer**: 如果需要独立的日志服务，部署 LoggerServer。
9.  **验证**: 通过 Web UI (默认 http://ApiServer_IP:12345/dolphinscheduler) 访问，并检查各服务状态。

详细的安装步骤请参考官方文档，不同版本可能会有差异。

### UI 概览

DolphinScheduler 提供了一个直观易用的 Web 用户界面，主要模块包括：

-   **首页/仪表盘**: 展示系统概览、任务状态统计、项目统计等。
-   **项目管理**: 管理项目信息，工作流定义和实例都在项目下组织。
-   **工作流管理**: 
    -   **工作流定义**: 创建、编辑、导入/导出、调度、运行、上线/下线工作流。
    -   **工作流实例**: 查看工作流的运行实例列表、状态、日志、重跑、停止等。
-   **任务管理**: 
    -   **任务实例**: 查看所有任务实例的详细信息、日志。
-   **资源中心**: 管理项目级别和用户级别的资源文件（如脚本、JAR 包）、UDF 函数。
-   **数据源中心**: 管理连接各种外部数据源（如 MySQL, PostgreSQL, Hive, Spark SQL）的配置信息。
-   **监控中心**: 查看 Master、Worker、数据库、ZooKeeper 等服务状态。
-   **安全中心**: 管理用户、租户、Worker 分组、队列、告警组、令牌管理等。
-   **用户中心**: 修改个人信息。

## 核心概念

理解以下核心概念有助于更好地使用 DolphinScheduler：

### 项目 (Project)

项目是 DolphinScheduler 中组织工作流的基本单元。所有的工作流定义、工作流实例、资源文件等都隶属于某个项目。用户可以创建项目并授权给其他用户。

### 工作流定义 (Workflow Definition / Process Definition)

工作流定义是一个 DAG (有向无环图) 的蓝图，它描述了一系列任务节点以及它们之间的依赖关系、执行顺序和调度配置。用户通过可视化界面拖拽任务节点并连接它们来创建工作流定义。

### 任务节点 (Task Node)

任务节点是工作流中的一个原子执行单元，代表一个具体的任务，如执行一个 Shell 脚本、一段 SQL 查询、一个 Spark 作业等。每个任务节点可以配置其类型、参数、资源依赖、执行用户、超时时间、重试策略等。

### 工作流实例 (Workflow Instance / Process Instance)

工作流实例是工作流定义的一次具体运行。当一个工作流被调度执行或手动触发时，就会生成一个工作流实例。每个实例有其独立的运行状态、开始时间、结束时间、日志等。

### 任务实例 (Task Instance)

任务实例是工作流实例中某个任务节点的一次具体运行。每个任务实例也有其独立的运行状态、日志、尝试次数等。

### 参数 (Parameters)

-   **全局参数**: 定义在工作流级别，该工作流下的所有任务节点都可以引用这些参数。
-   **局部参数 (节点参数)**: 定义在任务节点级别，通常用于节点内部的配置。
-   **内置参数**: DolphinScheduler 提供了一些内置参数（如 `${system.biz.date}` 代表业务日期, `${system.datetime}` 代表当前时间）供任务使用。
-   **节点间参数传递**: 支持上游节点的输出作为下游节点的输入，通过 "${setValue(key=value)}" 和 "${key}" 的方式实现。

### 租户 (Tenant)

租户用于实现资源的隔离。每个租户可以关联一个或多个 Linux 用户，任务会以该 Linux 用户身份在 Worker 节点上执行。租户也可以关联特定的 Worker 组和资源队列，实现计算资源的隔离。

### 资源中心 (Resource Center)

用于管理工作流执行所需的各种文件资源，如 Shell 脚本、Python 脚本、JAR 包、配置文件等。资源可以上传到 DolphinScheduler 管理的存储（如 HDFS 或本地文件系统）。

### 数据源中心 (Datasource Center)

集中管理连接外部数据存储的配置信息，如 JDBC URL、用户名、密码等。在 SQL 任务或其他需要访问外部数据的任务中，可以直接选择已配置的数据源，无需在任务脚本中硬编码连接信息。

## 工作流设计与管理

### 创建项目与工作流

1.  **创建项目**: 在"项目管理"页面，点击"创建项目"，填写项目名称、描述等信息。可以为项目设置权限，分配给特定用户。
2.  **创建工作流定义**: 进入项目后，在"工作流定义"页面，点击"创建工作流定义"。
3.  **绘制 DAG**: 在画布上，从左侧工具栏拖拽所需类型的任务节点（如 Shell, SQL, Python）到画布。通过拖拽节点间的连接桩，建立任务之间的依赖关系。

### 添加与配置任务节点

-   双击画布上的任务节点，或选中节点后点击编辑按钮，打开节点配置弹窗。
-   **常规配置**: 设置节点名称、运行标志（正常运行、禁止执行）、描述。
-   **参数配置**: 根据任务类型配置具体参数。
    -   **Shell**: 编写 Shell 脚本，选择或上传脚本资源。
    -   **SQL**: 选择数据源类型、数据源实例，编写 SQL 语句。
    -   **Python**: 编写 Python 脚本。
    -   **Sub_Process**: 选择一个已定义的子工作流。
    -   **Dependent**: 配置对其他项目或其他工作流中任务的依赖。
    -   **Conditions**: 编写条件表达式（通常基于上游任务的输出或全局参数）来决定分支走向。
    -   **Switch**: 根据输入参数的值选择执行哪个分支。
-   **资源**: 为任务关联资源中心的文件。
-   **前置任务**: 通常由 DAG 连线自动确定，也可手动检查。
-   **超时告警**: 配置任务执行超时时间和告警设置。
-   **失败重试**: 配置任务失败后的重试次数和重试间隔。
-   **任务组**: 分配任务到特定任务组，可用于资源管理和并发控制。
-   **Worker 分组**: 指定任务在哪个 Worker 组上执行。

### 配置依赖关系

通过在画布上从一个节点的输出连接桩拖拽到另一个节点的输入连接桩，即可建立依赖关系。一个任务可以依赖多个上游任务，也可以被多个下游任务依赖。

### 配置参数

-   **全局参数**: 在工作流定义编辑页面的"全局参数"标签页中添加。格式为 `prop=value`。
-   **任务节点参数**: 在任务节点配置中，根据具体任务类型设置。
-   **参数传递**: 
    -   上游任务使用 `echo "${setValue(my_var=hello_world)}"` 将 `my_var` 的值设置为 `hello_world`。
    -   下游任务可以通过 `${my_var}` 来引用这个值。

### 调度配置

1.  在工作流定义页面，选中工作流，点击"定时"。
2.  创建或编辑定时配置：
    -   设置起止时间。
    -   使用 Cron 表达式配置调度周期（如每天凌晨执行 `0 0 0 * * ?`）。
    -   配置失败策略（继续、结束）。
    -   设置通知策略和告警组。
    -   设置流程优先级。
    -   选择 Worker 分组。
    -   配置补数依赖方式。
3.  保存并上线定时。

### 版本管理

-   每次保存工作流定义时，都会生成一个新的版本。
-   可以在工作流定义列表页查看历史版本，并切换到任意历史版本进行查看或恢复。

### 上线与下线

-   工作流定义创建后默认为"下线"状态，需要"上线"后才能被调度执行。
-   定时调度也需要先"上线"工作流定义，然后上线定时配置。

## 工作流执行与监控

### 运行工作流

-   **手动运行**: 在工作流定义页面，选择工作流，点击"运行"。可以配置启动参数、失败策略、通知策略等。
-   **定时调度**: 工作流会根据已配置并上线的定时信息自动触发运行。

### 查看实例与日志

-   **工作流实例**: 在"工作流实例"页面，可以查看所有运行实例的列表，包括状态（提交成功、运行中、准备暂停、暂停、准备停止、停止、失败、成功、需要容错、终止、串行等待、派发）、开始时间、结束时间、运行时长等。点击实例名称可以进入 DAG 视图查看各任务节点的实时状态。
-   **任务实例**: 在"任务实例"页面，或从工作流实例的 DAG 视图中点击任务节点，可以查看任务实例的详细信息，包括执行日志、尝试次数、提交时间、Worker 地址等。
-   **查看日志**: 点击任务实例的"查看日志"按钮，可以滚动查看完整的执行日志。

### 失败重跑 (Rerun)

-   **从失败节点开始重跑**: 如果工作流实例因某个任务失败而整体失败，可以在该工作流实例页面选择"重跑"，系统会从失败的节点开始重新执行。
-   **重跑所有任务**: 也可以选择重跑整个工作流实例。

### 补数 (Complement)

-   用于对历史数据进行批量回填处理。
-   在工作流定义页面，选择工作流，点击"补数"。
-   配置补数的数据时间范围（通常是天级别）、并行度、依赖模式等。
-   DolphinScheduler 会根据配置生成对应日期范围内的多个工作流实例。

## 资源管理

### 文件管理 (Resource Center)

-   在"资源中心"页面，可以创建文件夹、上传文件（如 .sh, .py, .jar, .zip 等）。
-   上传的文件可以在任务节点配置时作为资源进行关联和使用。
-   支持管理 HDFS 上的资源文件 (需配置 Hadoop 环境)。
-   可以设置文件的别名，方便在脚本中引用。

### 数据源管理 (Datasource Center)

-   在"数据源中心"页面，创建和管理连接各种外部数据存储的配置。
-   支持的数据源类型包括 MySQL, PostgreSQL, Oracle, SQLServer, Hive, Spark, ClickHouse, Presto 等。
-   配置内容通常包括数据源名称、描述、类型、连接参数（IP、端口、用户名、密码、JDBC连接串等）。
-   配置好的数据源可以在 SQL 任务等节点中直接选择使用。

## 安全与租户管理

### 用户管理

-   管理员可以创建、编辑、删除用户，分配用户角色（管理员、普通用户）。
-   用户可以修改自己的密码和邮箱等信息。

### 租户管理 (Tenant)

-   租户是资源隔离的基本单位。
-   创建租户时，需要指定该租户对应的操作系统用户（Worker 节点上必须存在该用户）。任务会以此用户身份执行。
-   可以将租户关联到特定的 Worker 队列，实现更细粒度的资源控制。

### Worker 分组 (Worker Group)

-   可以将 WorkerServer 节点划分到不同的组中。
-   工作流定义或定时调度时，可以指定在哪个 Worker 组上执行。这常用于：
    -   隔离不同环境（开发、测试、生产）。
    -   隔离不同重要程度的任务。
    -   将特定类型的任务（如需要特定依赖库的 Python 任务）调度到已配置好相应环境的 Worker 组。

## 告警 (Alerting)

### 告警组 (Alert Group)

-   在"安全中心" -> "告警组管理33"中创建告警组。
-   一个告警组可以包含多个告警插件实例（如邮件、钉钉、企业微信）。

### 告警插件实例 (Alert Plugin Instance)

-   配置具体的告警发送方式和参数。
    -   **邮件**: 配置 SMTP 服务器、发件人、收件人等。
    -   **钉钉**: 配置 Webhook URL、关键词、@用户等。
-   创建好的告警插件实例可以被添加到告警组中。

### 配置告警

-   在工作流定义、定时调度、任务节点配置中，都可以关联告警组。
-   当工作流或任务达到触发条件（如成功、失败、超时）时，会向关联的告警组发送通知。

## 故障排查与最佳实践

### 常见问题排查

-   **日志分析**: 仔细阅读 MasterServer, WorkerServer, ApiServer 以及任务实例的日志，是定位问题的首要步骤。
-   **服务状态检查**: 通过监控中心或命令行检查各服务组件（Master, Worker, ZK, DB）是否正常运行。
-   **配置核查**: 检查 `common.properties` (或 `dolphinscheduler_env.sh`), `install_config.conf` 等配置文件中的数据库连接、ZK 地址、端口号等是否正确。
-   **网络问题**: 确认各节点间网络通畅，防火墙配置正确。
-   **资源问题**: Worker 节点磁盘空间、内存、CPU 是否充足。
-   **权限问题**: 检查租户对应的操作系统用户权限，文件资源权限等。

### 最佳实践

-   **合理规划项目和工作流**：保持工作流的原子性和模块化，避免单个 DAG 过于庞大复杂。
-   **规范命名**: 项目、工作流、任务节点、参数等使用清晰规范的命名。
-   **版本控制**: 充分利用工作流的版本管理功能。
-   **参数化设计**: 尽量使用参数（全局参数、局部参数、内置参数）来提高工作流的灵活性和可重用性。
-   **资源隔离**: 合理使用租户和 Worker 分组进行资源隔离。
-   **监控与告警**: 配置全面的监控和告警，及时发现和处理问题。
-   **资源文件管理**: 将脚本、JAR 包等通过资源中心统一管理。
-   **数据源管理**: 通过数据源中心统一管理数据库连接。
-   **定期维护**: 定期检查系统日志，清理过期实例和日志，监控数据库和 ZK 状态。
-   **性能调优**: 根据实际负载调整 Master/Worker 配置参数，如线程数、队列大小等。

本指南覆盖了 Apache DolphinScheduler 的主要功能和使用流程。更详细的信息和高级特性，请参阅官方文档和社区资源。
